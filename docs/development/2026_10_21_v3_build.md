## Departures from the plan, and why

1. **The fitted DD model is offered, not adopted (decision 3a).** The refit cannot identify the DD model's rate and onset constant from within-trial contrasts. Their posteriors reproduce their priors, so a "fitted DD" default would mostly encode assumptions. The calibrated DD of version 2 stays the DD model and the fitted DD is a labeled option. This needs Igor's confirmation (fit report section 7).
2. **The acute refit was not done.** The plan's Phase 3 suggested refitting the acute model to the 108 schedules of Pardo-Montero et al. 2021. The toxicity draws instead use stated priors (registered in `sim_provenance.yaml`), and the HYPNO-relative acute limit is recomputed under each draw, which cancels part of the acute uncertainty. The acute refit is the next statistical item.
3. **`app.R` was evolved, not split into one module per tab.** The two new tabs are Shiny modules, and every tab reads one `settings()` reactive. The existing tabs stay in `app.R` so that the 2727 version 2 tests keep testing the same server code. A full split is a refactor with no change in behavior and can follow.
4. **No `ExtendedTask`.** The installed Shiny supports it, but it needs the `promises`/`future` stack, which is not in the release library. The search under uncertainty runs on a button (about 2 s with 1000 draws) with a progress bar instead.
5. **DVH formats.** The Eclipse text parser is written to the layout of Eclipse exports and tested on synthetic files, not on a real export. RayStation's own format was not available, so a generic two-column CSV (dose, volume, optional structure) stands in for it. The first real export should be checked against the planning system's mean and maximum.
6. **Organs without a verified conventional constraint** (mandible, constrictors, oral cavity, cervical esophagus, brachial plexus) are assessed with the HYHOPE library only. HYPNO's appendix E1, which would give the DAHANCA source values, is not in the local files.
7. **The both-model screen's default changed** because of decision 7a. At the global defaults (35 × 2 Gy, +1 Gy) it opens empty. HYPNO and −3 Gy restore the version 2.7 list of 17, 18 and 19 fractions (test `test_v3_app.R::README claim ...`).
8. **A wrong correction, reverted.** I first changed About reference 6 from protocol "version 4.2" to "4.1" because the body page headers read 4.1. The signature page reads "Version 4.2", as `References/README.md` already recorded, so 4.2 is correct. The wrong change was committed in `1404f3a` and reverted in the next commit, after the v2.5 test that pins "version 4.2" failed on it.

## Findings during the build

- Overdispersion: Pearson χ²/df 3.65 (DI), 3.41 (DD) with per-trial intercepts.
- The published DD preference (AICc difference about 40) does not survive per-trial intercepts: maximum-likelihood difference 1.96 log-likelihood units. Leave-one-trial-out difference −0.06 ± 1.86.
- Dropping the last week of 35 × 2 Gy loses tumor BED under both refits (DI median −6.0 Gy₁₀, 95% of draws below zero), unlike the 2018 paper's conclusion.
- Table 2 of the 2018 paper has the DI and DD onset labels swapped.
- HYHOPE's 12/15/20-fraction tables are not one exact LQ conversion: the per-organ EQD2 differs by up to 6.5% across tables. The validation fixture asserts agreement within 7% and pins the spreads.
- Bug found by the new app test and fixed before commit: `load_draws()` set its SHA-256 and ESS attributes before subsetting columns, which drops attributes, so uncertainty replay could not verify its draws and the Monte Carlo error used the raw draw count.
- Engineering: launching a newly compiled Stan binary inside OneDrive appeared to fail with "Operation not permitted". The real cause was Stan's default random initial values (α up to e² per Gy, which makes tumor control exactly 0 or 1). Explicit, jittered initial values fixed it. Compilation and raw chains were moved outside OneDrive as well.
- Engineering: Windows git could not read the worktree pointer (a Linux path), so `tools/run_tests.R` could not record the passing revision. The pointer is now relative.
