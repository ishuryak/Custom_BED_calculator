# Version 2.6: response to the external review of 2.5.1

19 October 2026. Reviewed snapshot: `451d4c5` (app 2.5.1, equation 2.2, selection 2.5). External review: `docs/development/2026_10_19_external_review_v251_codex.md` (copy of `HNSCC_BED_v251_review_and_action_plan_2026-10-19.md`. Its evidence package was read but is not copied here). Work done by Claude (Opus 5.5) for Igor Shuryak, who asked for the review to be acted on autonomously, to get the app into good shape for clinical use as an exploratory tool. Decisions taken without him are listed in section 3 for confirmation.

## 1. Bottom line

Every finding R1 to R9 was checked against the code before it was acted on, and every one held. R1 is a ranking defect that can list a regimen the validity rule rejects; R2 to R9 are replay, interpretation, wording, verification and environment gaps. All nine are addressed. No equation, default or acute policy changed, and the default candidate rows (29 × 2.25, 28 × 2.30, 30 × 2.20 Gy) and agreement rows (17 × 3.05, 18 × 2.90, 19 × 2.80 Gy, 15 of 15) are unchanged. What moves: the listed regimen in edge cases where one model's BED is not positive (R1), agreement ranges where some scenarios are not evaluable (R5), and which old scenario files replay without an explicit migration (R3).

The app is now suitable as an exploratory screen of explicit hypotheses, with the limitations stated on its Model page. It remains a BED calculator: it has no dose-response relation, no organ-at-risk doses, no chemotherapy effect and no uncertainty propagation, and a passing test suite is not clinical validation.

## 3. Decisions taken without the PI (please confirm or reverse)

- **B1.** "Larger change" ranking keeps using whichever model is evaluable (documented optimistic fallback). "smaller change" requires both. Alternative: require both for every two-model ranking.
- **B2.** Qualifying but unrankable regimens are not listed. They stay in `all_qualifying.csv` with `rank_eligible` FALSE, and an all-unrankable search gives its own message.
- **B3.** Agreement ranges over jointly evaluable scenarios (the review's preferred option), not per-model ranges.
- **B4.** No historical engine is kept: version 2.5 and older files need explicit `migrate_scenario()`. This also applies to 2.5 schema-2 exports made earlier today.
- **B5.** Redundant agreement fields are enforced rather than removed, so the schema stays at 2.
- **B6.** No advanced anchor-time control. The reproduction instructions were narrowed instead.
- **B7.** The HYPNO illustration stays on the Model page (the PI's earlier choice), as text with stated assumptions, not as an app computation.
- **B8.** The release library uses newer package versions than the user library had (for example shiny 1.14.0, digest 0.6.39, testthat 3.3.2). This is a dependency upgrade. The full suite gives the same results in it (2541 expectations, 0 failed, 0 warnings), and the default rows are pinned by tests.
- **B9.** Source hashing reads bytes instead of `digest(file = ...)`. The review advised investigating first. The cause is `digest`'s `file.access()` precheck, which on the reviewer's Windows token denied readable files. The SHA-256 of the bytes is identical (pinned by a test), so the change removes a false failure without changing any hash.

## 5. What this does not establish

- That any listed regimen is effective or safe. The calculator screens BED. The HYPNO illustration is conditional on assumptions it cannot test.
- Browser behavior beyond the automated checks: keyboard-only navigation, browser zoom, screen readers and browsers other than Chrome were not tested.
- A clean run on a different computer. The clean restore was into an empty library on this computer; CI on GitHub repeats it on Linux once pushed.
